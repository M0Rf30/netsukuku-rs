# Vala rewrite: services & daemon (zcd, tasklet-system, peerservices, andna, ntkd)

Open this for the wire format, the concurrency model underneath it, and the parts of the daemon
that never got past a stub upstream — zcd framing, tasklet-system/pth-tasklet, PeerServices, ANDNA,
and how ntkd shells out to `ip`/`iptables`/`sysctl`. Companion to `01`, which covers the routing core.

Scope: wire protocol (zcd), concurrency model (tasklet-system/pth-tasklet),
peer-to-peer substrate (peerservices), name service (andna — unimplemented),
daemon wiring (ntkd/system-ntkd), test harnesses (sys-ntkd-alone,
sys-ntkd-test1, proof). qspn/hooking/coordinator/neighborhood/identities
internals out of scope; referenced only where ntkd wires them.

peerservices@6cdfdf5, andna@1ae7596, ntkd@d5e7798, ntkdrpc@ba88fab,

## 1. zcd — wire protocol

Two layers: **zcd** (transport+framing+JSON envelope) and **MOD-RPC**
(codegen'd stub/skeleton on top, generated by `rpcdesign` from
`interfaces.rpcidl`). `ntkdrpc` is the MOD-RPC instance ntkd actually uses.

**Transports** (chosen per call site, not negotiated):
`stream_net_listen`/`send_stream_net` = TCP (`zcd/listeners.vala:46-59`,
`senders.vala:27-44`); `stream_system_listen`/`send_stream_system` = AF_UNIX
stream; `datagram_net_listen`/`send_datagram_net` = UDP broadcast
(255.255.255.255) via `SO_BINDTODEVICE`+`SO_BROADCAST`
(`pth-tasklet/tasklet_blocking_sockets.vala:181-241`);
`datagram_system_listen`/`send_datagram_system` = AF_UNIX datagram. Stream
sockets pooled per destination key (`senders.vala:24-116`); a dead pooled
socket is discarded and retried once with a fresh connection.

**Framing** (stream only): 4-byte big-endian length prefix + UTF-8 JSON,
`max_msg_size = 10_000_000` (`zcd/connection_protocol.vala:34-141,57`).
Datagrams are unframed, `max_pkt_size = 60_000` (`zcd/listeners.vala:318`) —
one packet = one message, no reassembly.

**JSON envelope** (`zcd/json_handling.vala`):
- Unicast request (stream), root object, 6 members: `method-name` (string),
  `arguments` (array of pre-serialized JSON subtrees), `source-id`,
  `unicast-id`, `src-nic` (objects), `wait-reply` (bool) — lines 31-192.
- Unicast response: `{"response": <any root node>}` — lines 194-244.
- Broadcast/datagram packet: root object with exactly one member, `"request"`
  or `"ack"` (lines 246-383). `request`: `packet-id`(int), `method-name`,
  `arguments`, `source-id`, `broadcast-id`, `src-nic`, `send-ack`(bool).
  `ack`: `packet-id`, `src-nic`.
- Every id field (`source-id`/`unicast-id`/`broadcast-id`/`src-nic`) is a
  MOD-RPC object: `{"typename": <GType name>, "value": <gobject_serialize>}`;
  deserialize does `Type.from_name(typename)` — requires the receiver to have
  already touched the class via `typeof(X).class_peek()`
  (documentation/ita/Librerie/ZcdDettagliTecnici.md:893-903).
- Datagram ACK: receiver of a `send-ack` request resends `ack{packet-id,
  src-nic}` 3× at random 10–200ms (`zcd/listeners.vala:576-627`) —
  best-effort, no request retransmission, only ack retransmission.

**Argument serialization** (MOD-RPC): int64/double/bool/string → VALUE node;
`uint8[]` → base64 VALUE; `GLib.Object`/interface → OBJECT
`{typename,value}`; `Gee.List<T>` → ARRAY of per-element nodes; nullable+null
→ NULL node (ZcdDettagliTecnici.md:846-886). No other types without a
hand-written `Json.Serializable`.

**Request/response vs one-way**: stream mode carries `wait_reply`; if false
(or any datagram call) and the method is non-void, stub raises
`StubError.DID_NOT_WAIT_REPLY` locally (`ntkdrpc/api.vala:23-27`). Datagram is
inherently fire-and-forget; reliability is opt-in via `send_ack` +
`IAckCommunicator.process_src_nics_list`, no request retransmission.

**Error model** (`ntkdrpc/api.vala:23-32`): `StubError{DID_NOT_WAIT_REPLY,
GENERIC}` is local-only, never serialized. `DeserializeError{GENERIC}` is
raised server-side on bad args (wrong node kind, unknown typename, type
mismatch, missing members, or `check_deserialization()`→false) and travels
back as the RPC outcome; also raised client-side on bad return value. Wire
shape one level below zcd's `response`: `{"return-value": ...}` or
`{"error-domain","error-code","error-message"}` (ZcdDettagliTecnici.md:
1013-1023); undeclared error-domain → `DeserializeError`. Every remote method
effectively gets `throws ..., StubError, DeserializeError` appended by the
generator (real list in `ntkdrpc/interfaces.vala:33-67`).

**Codegen** (`zcd/rpcdesign.vala:1-301`): DSL `Root class name` /
indented `Module class name` / doubly-indented `type method(args) throws
E1,E2` + `Errors` block `Domain(CODE1,CODE2)`. Example root in
`ntkdrpc/interfaces.vala:20-224`: `AddressManager addr` with modules
`NeighborhoodManager, IdentityManager, QspnManager, PeersManager,
CoordinatorManager, HookingManager` — **no `AndnaManager` module declared**
(see §4). Outputs: `common_helpers.vala`, `interfaces.vala`, `api.vala`
(`StubError`, `DeserializeError`, `IDelegate`, `IErrorHandler`,
`IListenerHandle`, `ISerializable`), `caller_info.vala`,
`common_skeleton/stub.vala`, per-root `xxx_skeleton/stub.vala`. Skeleton
methods take an extra `CallerInfo? caller=null`; `IDelegate` can return 0..N
root-skeletons per message (multi-identity dispatch). Stub factories are one
function per (root, medium): `get_node_manager_stream_net(peer_ip, tcp_port,
source_id, unicast_id, src_nic, wait_reply)`, `..._datagram_net(my_dev,
udp_port, source_id, broadcast_id, src_nic, notify_ack=null)`.

**Rust implication**: framing is trivial (`serde_json` + custom 4-byte-BE
length codec). The `{typename,value}` polymorphic envelope needs a
deliberate replacement since Rust has no `Type.from_name`; likely an
explicit tag→type registry rather than `serde`'s built-in enum tagging.

## 2. tasklet-system + pth-tasklet — concurrency model

`tasklet-system` is a pure interface package (`ITasklet`, `ITaskletHandle`,
`ITaskletSpawnable`, `IChannel`, socket interfaces,
`tasklet_system.vala`) — a hand-rolled async trait every layer above codes
against. `pth-tasklet` is the only implementation: cooperative M:1
green-thread scheduler on GNU Pth.

- **Tasklet** (`pth-tasklet/tasklet.vala:78-495`): one Pth thread per
  tasklet; `schedule(next=null)` cooperatively yields (`pth_yield`);
  `nap(sec,usec)` sleeps only the caller; `exec_command` runs a real
  subprocess, pumping stdout/stderr non-blockingly while yielding.
- **spawn(sp, joinable=false)** → `ITaskletHandle{is_running, kill,
  is_joinable, join}` (`tasklet_system.vala:27-33`,
  `pth-tasklet/tasklet_system_tasklet.vala:74-116`). `kill()` = `Pth.abort()`
  — unconditional, not a cooperative cancellation token.
- **IChannel** (`tasklet_system.vala:108-120`, impl `channel.vala`): boxed
  `GLib.Value`; `send` blocks sender until received, `send_async` never
  blocks (queues), `recv`/`recv_with_timeout` (`ChannelError.TIMEOUT`),
  `get_balance` (>0 queued messages, <0 waiting receivers), FIFO receiver
  order enforced (`channel.vala:106-166`). This is the base sync primitive —
  peerservices' `WaitingAnswer.ch` (§3) is exactly one send_async +
  one recv-with-timeout per outstanding RPC, i.e. a oneshot.
- **DispatchableTasklet** (`tasklet_system.vala:154-215`): work queue over
  one persistent tasklet, `dispatch(sp, wait_end, wait_start)`. Used by
  `ntkd/commander.vala` to serialize all `ip`/`iptables` calls onto one
  tasklet (§5) and by `system-ntkd/fake_command_dispatcher.vala` likewise.
- **Blocking sockets** (`pth-tasklet/tasklet_blocking_sockets.vala`): thin
  wrappers where `accept`/`connect`/`send`/`recv`/`recvfrom` go through
  `PthThread.socket_*` (Pth's poll-based emulation) — only the calling
  tasklet blocks. No separate IPC primitive beyond these sockets; zcd's
  framing (§1) is built on top.

**Rust async implications**: tasklets ≈ cooperative tasks on a *single*
scheduler; module-level mutable state throughout ntkd (bare `ArrayList`s,
no locks) relies on Pth's "only yields at blocking calls" guarantee. Porting
onto a multi-threaded Tokio runtime without adding explicit
`Mutex`/`RwLock`/actor boundaries at every such site introduces races that
don't exist in the source — audit this deliberately, don't port literally.
`IChannel` → `tokio::sync::{mpsc,oneshot}` + `tokio::time::timeout`;
blocking `send` has no direct equivalent and isn't needed (observed usage is
always "wake exactly one correlation-id waiter"). `DispatchableTasklet` →
single-consumer mpsc + one task looping recv. `ITaskletHandle.kill()` (Pth
abort) has no safe async-Rust analog; prefer `CancellationToken`/drop-based
cancellation from the start.

## 3. peerservices — DHT-over-topology

Core files: `peers.vala` (`PeersManager`, registration/glue),
`message_routing.vala` (routing/retry state machine), `databases.vala`
(replica algorithms, TTL/fixed-key DB abstractions), `map_handler.vala`
(participation-map gossip), `utils.vala` (tuple/HCoord arithmetic),
`serializables.vala` (wire types).

**Address space**: `PeerTupleNode{tuple:List<int>}` /
`PeerTupleGNode{tuple,top:int}` — `tuple[0]` is the outermost level below
`top`; `level = top - tuple.size` (`serializables.vala:23-207`).
`check_valid` bounds each `tuple[i]` against `gsizes[level+i]`.

**Key→g-node mapping**: `IDatabaseDescriptor.evaluate_hash_node(key) ->
List<int>` produces a target tuple in the same address space
(`databases.vala:46-56`) — the "hash ring" *is* the hierarchical NIP space,
not a separate flat space. **Distance**: `dist(x̄,x)`
(`message_routing.vala:155-167`) is per-level modular (circular) distance in
mixed-radix `gsizes[j]` — Chord-style finger distance over the g-node
hierarchy. `approximate(x̄, exclude_list)` (lines 169-234) picks the
minimum-`dist` real (non-virtual) candidate among visible g-nodes — the
"find responsible node" step.

**`contact_peer` flow** (`message_routing.vala:267-572`, wrapped by
`PeersManager.contact_peer`, `peers.vala:514-529` for participation-map
waiting): per attempt — (1) compute `exclude_gnode_list` from known
non-participants + caller excludes; (2) `approximate()` a target, build
`PeerMessageForwarder{msg_id,p_id,n,x_macron,exclude_tuple_list,
non_participant_tuple_list}`, forward hop-by-hop via gateway stubs until a
node is `am_i_servant_for` it (`peers.vala:408-416`); (3) register
`WaitingAnswer` keyed by `msg_id`, block on channel with
`find_timeout_routing(nodes)`: 200ms base, 2000ms if group >100 nodes,
20000ms if >1000, `min_timeout=500` floor (`message_routing.vala:243-255`);
(4) wake on `response` (success), `refuse_message`+`e_lvl`, `redo_from_start`
/`missing_optional_maps` (restart from step 1), or timeout (exclude the
failed gnode, retry); (5) on timeout also best-effort notify the
respondant via `set_redo_from_start` (lines 679-704,832-841).

**refuse/redo semantics**: server `exec_service` throws
`PeersRefuseExecutionError{WRITE_OUT_OF_MEMORY,
READ_NOT_FOUND_NOT_EXHAUSTIVE, GENERIC}` (`peers.vala:57-61`) with level
embedded as text `"...level=$(e_lvl)"`, parsed back out
(`extract_level_from_refuse_execution_message`, `message_routing.vala:65-76`
— stringly-typed, a wire-compat wart to not preserve literally). Client
keeps ≤10 rotating refuse messages (`message_routing.vala:340-347`) and
widens `exclude_gnode_list` to every g-node up to `e_lvl` ("whole subtree
refused, try a different branch"). `redo_from_start` invalidates the entire
address computation — outer `while(redofromstart)` loop reruns from scratch
(line 281-284), distinct from `PeersRedoFromStartError` (a server-exec-level
error making the *server* re-drive routing before answering). Every
secondary/notification stub call (redo/refuse/gossip) swallows
`StubError`/`DeserializeError` as best-effort-ignore; only the primary
request/response path treats timeout as a hard failure.

**Participation maps/gossip**: `PeerParticipantMap{participant_list:
List<HCoord>}`, `PeerParticipantSet{my_pos, retrieved_below_level,
participant_set: Map<p_id,PeerParticipantMap>}`
(`peers.vala:143-159,325-359`). New network: `maps_retrieved_below_level =
levels` (trivially complete). Entering a network at `guest_gnode_level`:
seed from own prior knowledge, spawn `retrieve_participant_set()` walking
neighbors at `host_gnode_level-1` via `ask_participant_maps()` until a
deeper validated map returns, then `copy_and_forward`
(`map_handler.vala:139-301`) — folds incoming per-node maps to *my*
g-node granularity at the "maximum distinct g-node" level, merges new
levels via `add_participant`, then flood-gossips onward (`retrieved_below_
level` monotonic freshness test; broadcast with per-arc missing-arc→unicast
fallback→`failing_arc` signal on failure, never blocks indefinitely on one
arc). New local participation is separately push-gossiped on
`participate(p_id)`.

**Constants/IDs**: `p_id:int` is caller-assigned, no fixed enum in this
corpus; unique per `PeersManager.register(PeerService)`
(`peers.vala:397-406`); unknown `p_id` defaults to "optional, unknown"
(safe against unrecognized service IDs). `min_timeout=500`ms floor plus
200/2000/20000ms node-count bands. `eval_coherence_delta`: 2000/20000/30000/
50000ms at <50/<500/<5000/≥5000 nodes (`databases.vala:167-173`, TTL-DB
logic, not detailed further here). Replication factor `q` is a per-call
param to `begin_replica`/`next_replica` (`databases.vala:246-292`), not
global — each `next_replica` re-`contact_peer`s excluding every prior
respondant until `q` replicas collected or routing exhausted.

## 4. andna — NOT IMPLEMENTED in this corpus

`andna/andna.vala` is a 13-line stub: `AndnaManager.init()` just stores the
tasklet; no fields/methods; `andna/serializables.vala` is a 0-byte file.
`ntkd` wires it anyway with a literal `// AndnaManager TODO`
(`ntkd/startup.vala:249-252`), and `ntkdrpc/interfaces.vala`'s module list
**omits `AndnaManager` entirely** — consistent with the design docs' own
unfinished-work notes (`documentation/ita/note-ntkd.md:936-937`,
`.../Assemblaggio/CasoBanaleImplementazioneTestsuite/ComunicazioniRete.md:
183-184`). No ANDNA RPC method, record type, or serializable exists here.

Only design content available (Dionisi's own doc, not the C/Alpt spec —
`03-specs-and-rfcs`'s territory):
`documentation/ita/DemoneNTKD/RisoluzioneNomi.md` (full text read):
flat namespace, bounded-length case-insensitive alnum name; **256 names/node
cap** (lines 50-52); **30-day TTL**, renewal resets counter, renewal
authenticated by the owning node via **asymmetric-key** crypto, scheme
unnamed (lines 54-57); backend = "two peer-to-peer services, **Andna** and
**Counter**", mechanics explicitly out of that doc's scope (lines 63-65;
`Counter` presumably enforces the 256-cap — `[INFERENCE]`, name unconfirmed
elsewhere). Front end: server = ntkd itself (unimplemented); client =
`libnss_andna.so`, `dns-to-andna`, `ntk-resolv` — none present in this
corpus (`documentation/ita/Home.md:15-29,98-103`, "TODO" in the doc). No
record schema, replication factor, or collision algorithm exists in the
Vala tree; must come from `research/impl/c/netsukuku` + RFCs.

## 5. ntkd + system-ntkd — daemon wiring

**CLI** (`ntkd/ntkd.vala:111-146`): `-s/--subnetlevel <int>` (g-node level
for autonomous-subnet/NAT boundary, default 0), `-i/--interfaces <dev>`
(repeatable), `-k/--serve-anonymous`, `-j/--no-anonymize`. **No config-file
flag**: `configuration.vala:31-68` hardcodes topology `g_exp=[2,1,1,1]`
(`gsizes=[4,2,2,2]`) and a random start address — no `ntk.conf` consumption
in the daemon itself. The `ntk.conf` files under `system-ntkd/`,
`sys-ntkd-alone/`, `sys-ntkd-test1/` are `/etc/iproute2/rt_tables`
**fragments** (51 lines, table ids 200–251 → `ntk`/`reserved_ntk_from_<id>`),
installed manually before the daemon runs, not app config.
`hooking_epsilon` (per-level migration search radius) is derived: smallest
level count whose cumulative `g_exp` reaches 5 bits (`configuration.vala:
49-63`).

**Kernel facilities**: all via shelling out to `ip`(8)/`iptables`(8)/
`sysctl`(8) — no netlink library, no TUN, **no IPv6 anywhere** (grep for
ipv6/AF_INET6/inet6 across ntkd: no matches). `ntkd/commander.vala` wraps
`tasklet.exec_command_argv` in singleton `Commander`
(`single_command`/`begin_block`/`single_command_in_block`/`end_block`,
serialized onto one `DispatchableTasklet`), aborts the process on nonzero
exit (`commander.vala:24-37,94-119`). `TableNames`
(`ntkd/table_names.vala`) hands out ids 200–250 (251=`ntk`) per peer-MAC,
rewriting `/etc/iproute2/rt_tables` via `sed -i` (lines 45,66-114) — names
recycled, not created/destroyed.

Exact commands (all IPv4, `10.0.0.0/8`):
- `ip address add/del <cidr> dev <dev|lo>` (`identity_ip_commands.vala:
  36-49,207-232,852-865`).
- `sysctl net.ipv4.ip_forward=1`, `.conf.all.rp_filter=0`,
  `.conf.<dev>.rp_filter=0/.arp_ignore=1/.arp_announce=2`, `ip link set dev
  <dev> up` (`startup.vala:84-123`).
- `ip rule add/del table ntk` (main identity); `ip rule add/del fwmark
  <tid> table <table>` (per-peer-mac policy routing) —
  `identity_ip_commands.vala:89-90,157-158,316-317,700,791`.
- `ip route add/del/change unreachable <cidr> table <ntk|table>` (no known
  path) and `ip route change <cidr> via <gw_ip> dev <gw_dev> table <...>
  src <local>` (path exists) — lines 95-103,533-560,648-659.
- `ip route flush table <table>` on teardown — lines 156,743,766,803.
- `ip netns exec <namespace> <ip ...>` prefix for every **non-main
  identity** command (lines 350-351,388-389,481-482,520-521,634-635,757-758)
  — each secondary identity lives in its own netns (Identities module,
  boundary only: `IdentityData.network_namespace`, `ntkd.vala:223-229`).
- `iptables -t mangle -A/-D PREROUTING -m mac --mac-source <mac> -j MARK
  --set-mark <tid>` ties fwmark rule to a neighbor's MAC (lines
  159-162,313-315,745-748,769-771,804-806).
- `iptables -t nat -A/-D POSTROUTING -d <anon_range> -j SNAT --to <global>`
  (anonymizer, disabled by `--no-anonymize`).
- `iptables -t nat -A/-D PRE/POSTROUTING ... -j NETMAP --to ...` (subnet
  netmap when `subnetlevel>0`, lines 60-88,236-270; ranges in
  `ipv4_compute.vala:218-275`).

**NIP↔IPv4** (`ipv4_compute.vala`): all addresses in `10.0.0.0/8`. 32-bit
accumulator built level-by-level (`ip <<= g_exp[c]; ip += n_addr[c]`, high
level first), with a 2-bit kind prefix: `0`=global/public, `1`=internal
(embeds `inside_level`), `2`=anonymizing (lines 23-168). G-node addresses
zero low levels and compute CIDR prefix from summed zeroed `g_exp` bits
(lines 73-207). Netmap ranges are compositions of the same primitives
parameterized by `subnetlevel` (lines 209-275) — pure, stateless,
deterministic; best 1:1 Rust port target (no async/IO).

**Crash-recovery tool** (`ntkd/cleaning/cleaning.vala`, separate `ntkclean`
binary, not daemon signal handling): `ip netns list`→delete `ntkv*`;
`ip link show`→delete `macvlan` matching `/ntkv.+:/`; flush+delete `ip
rule`/`ip route` tables 200–251; regex-parse `ip route list`/`ip address
show` for leftover 169.254.*/10.* addresses and remove; regex-parse
`iptables -L ... mangle|nat -n` to reconstruct and `-D` every `MARK`/
`NETMAP` rule this daemon could have installed (lines 61-298+). "Diff
observed kernel state against naming convention, then undo" rather than
transactional teardown — useful pattern for Rust port's test/dev loop.

**mainloop/cleanup**: 100ms poll on a `do_me_exit` flag set from
SIGINT/SIGTERM handlers (`mainloop.vala:31-42`), no epoll — all real work is
on tasklets spawned during `startup()`. `cleanup()` tears down non-main
identities (namespace removal + `IpCommands.connectivity_stop`), then main
identity (`qspn_mgr.destroy()`, disconnect signal handlers,
`IpCommands.main_stop`), then kills RPC listener tasklets and the Pth
scheduler (`cleanup.vala:31-108`). **`startup()` ends with a literal `//
TODO continue`** (line 254) — committed daemon only ever brings up the
*first* identity; no steady-state "accept new arcs/NICs" loop in this file.

## 6. Test/simulation harnesses

Two generations:

**`proof`** (2017, real multi-host): manual `ssh`-scripted integration test.
`proof/testbeds/test1.txt` is a shell transcript: real `macvlan`
sub-interfaces on real hosts (alfa/beta/lambda/rho), driving a `qspnclient`
CLI (`proof/user_commands.vala`, 108KB) with literal commands
(`add_real_arc <my_mac> <peer_mac> <metric>`, `prepare_enter_net_phase_1`,
`enter_net_phase_1`, `add_qspn_arc`, `quit`), interleaved with real `ip link
add ... type macvlan`/`ip route add` on other hosts to hand-simulate
multi-hop topology (test1.txt full text). 4 testbeds exist; requires real
hosts/root, not reproducible in a single process.

**`system-ntkd`/`sys-ntkd-alone`/`sys-ntkd-test1`** (2019-2020, current):
single-host multi-process simulation. Each node = one process
(`./system_ntkd -i <dev>... -p <fake_pid> [-t <task>]... [--topology
g,g,g,g] [--firstaddr a,b,c,d]`, `system_ntkd.vala:137-256`); adjacency
emulated over **AF_UNIX datagram sockets**, not real NICs, by two proxy
daemons: `eth_domain -i <name>...` (full-mesh broadcast relay: listens
`send_<name>`, relays to `recv_<name>` of every other declared name —
inverted-prefix naming, `zcd/eth_domain_src/eth_domain.vala:44-50`) and
`radio_domain -i <in>... -o <out>...` (asymmetric one-way relay, simulating
non-symmetric radio reachability). `system_ntkd` never touches the real
kernel: `identity_ip_commands.vala` there calls `fake_cm.single_command`
(`FakeCommandDispatcher`) which only logs timestamped argv into an
in-memory `all_commands` list — the assertion surface for golden-output
tests. `sys-ntkd-alone`/`sys-ntkd-test1` keep the real `Commander` (no
`fake_cm`) — meant to run for-real as one node (see `sys-ntkd-alone/README`
→ "CasoBanale" trivial single-node deployment doc).

Scenario scripting via `--tasks name,arg,...` strings scheduled onto
tasklets after `ms_wait`: `do_prepare_enter,<ms>,<idx>,<enter_id>`,
`do_finish_enter,<ms>,<idx>,<enter_id>,<network_id>,<guest_lvl>,<go_pos>,
<in_g_naddr:...>,<in_g_elderships:...>`, `same_network,<ms>,<idx>,<dev>,
<peer_mac>,<id_peer_mac>`, `another_network,<ms>,<idx>,<dev>,<peer_mac>,
<id_peer_mac>,<network_id>` (`task_enter_network.vala:45-206`,
`task_simulate_hooking.vala:44-203`) — fake-signal injection harness,
directly invoking internal handlers (`EnterNetwork.prepare_enter/enter`,
`UpdateGraph.add_arc`) that real ntkd only reaches via QSPN/RPC signals,
keyed by a small `local_identity_index` (registration order, unlike real
ntkd's `NodeID`-keyed map). Bash drivers
(`system-ntkd/testsuites/scripts/test_*`) launch N proxies + N
`system_ntkd`s with staggered sleeps, redirect stdout/stderr, `kill`+`wait`
+assert exit codes; cleanup removes local-socket files matching

## Open questions / risks for the Rust port

1. **ANDNA has zero implementation to port** — record types, replication,
   collision handling, and registration/renewal RPCs must come from
   `research/impl/c/netsukuku` + the RFCs, not this corpus; budget as
   from-scratch design, not translation.
2. **`p_id` has no canonical registry** in this corpus — check the C impl
   before inventing service numbering, or move to string/UUID service names.
3. **`{typename,value}` polymorphic envelope assumes a process-wide open
   type registry** — Rust has no `Type.from_name`; needs an explicit
   registry/enum decision, a protocol-compat fork point if wire
   interop with the original format is ever a goal.
4. **`e_lvl` is smuggled through a formatted exception message string**
   rather than a structured field — treat as a Vala idiom to fix, not a
   wire contract to preserve; make it a real struct field in Rust.
5. **No IPv6 anywhere.** Wanting IPv6 or a real-netlink (vs shelled `ip`)
   backend means designing the whole `ipv4_compute.vala` address-encoding
   scheme and every `identity_ip_commands.vala` template fresh — no
   dual-stack precedent to mirror.
6. **Daemon wiring is unfinished past first-identity bootstrap**
   (`startup.vala`'s `// TODO continue`) — no reference implementation here
   for the steady-state "accept new arcs/NICs while running" loop.
7. **Cooperative-scheduler assumptions are pervasive and implicit**
   (unlocked module-level mutable state, correct only because Pth never
   preempts between yield points). Naive port to multi-threaded Tokio
   introduces races that don't exist in the source — scope a deliberate
   audit of which shared state needs a lock/actor boundary.
8. **`system-ntkd`'s `--tasks` DSL is positional with hard-coded arg counts,
   no schema/versioning** — if the Rust port keeps a scripted-harness
   feature, use a structured (JSON/TOML) scenario format from day one
   instead of porting the string DSL literally.
